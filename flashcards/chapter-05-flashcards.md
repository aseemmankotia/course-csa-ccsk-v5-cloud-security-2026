## Chapter 5: Domain 6: Security Monitoring — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Control plane logs vs data plane logs — what's the difference? | Control plane = logs of management/API actions (create/modify/delete resources — e.g., CloudTrail, Activity Log, Cloud Audit Logs). Data plane = logs of actual workload/data activity (app logs, DB queries, object access). Exam tip: control plane logging is often on by default and low-cost; data plane logging usually must be explicitly enabled and generates far higher volume. |
| 2 | Three core telemetry types tested in this domain? | Metrics (aggregated numeric time-series, e.g., CPU%), Logs (discrete timestamped events), Traces (request path/latency across distributed services). Exam tip: a scenario about tracking a request's path through microservices points to Traces. |
| 3 | What does CSPM stand for and what does it do? | Cloud Security Posture Management — continuously scans cloud resource configurations against security baselines to detect misconfigurations and drift (e.g., public storage buckets, overly permissive IAM). Exam tip: CSPM = configuration compliance; SIEM = log correlation/alerting. Don't confuse the two. |
| 4 | Common log retention benchmark cited on the exam (PCI DSS 10.5.1) | Minimum 1 year total retention, with at least 3 months immediately available in hot/searchable storage. Exam tip: use this as the reference model for 'hot tier vs archive tier' retention questions. |
| 5 | What makes log storage 'tamper-evident'? | WORM (Write Once Read Many) / object-lock immutable storage, cryptographic hash chaining, and separation of duties so log writers can't delete/modify entries. Exam tip: encryption alone does NOT provide tamper-evidence — it protects confidentiality, not integrity. |
| 6 | SIEM vs SOAR — what's the difference? | SIEM (Security Information and Event Management) aggregates, normalizes, and correlates logs to generate alerts. SOAR (Security Orchestration, Automation and Response) takes those alerts and automates the response/playbook actions. Exam tip: SIEM detects, SOAR responds. |
| 7 | Why centralize logs to a dedicated log archive account? | Prevents tampering if a workload account is compromised, enables cross-account correlation, and simplifies retention/compliance management. Exam tip: common trap — the management/root account does NOT automatically capture child account activity; per-account logging usually must be explicitly enabled. |
| 8 | What do network flow logs capture, and what do they NOT capture? | Capture traffic metadata: source/destination IP, port, protocol, bytes, accept/reject decision. Do NOT capture packet payload/content. Exam tip: use flow logs for anomalous traffic pattern detection, not deep packet inspection (that's IDS/IPS/DPI). |
| 9 | Best practice for visibility across distributed multi-cloud workloads? | Centralized log aggregation with a normalized common schema, consistent telemetry collection (metrics/logs/traces) across all providers, feeding one SIEM/SOAR for correlated alerting. Exam tip: siloed per-provider dashboards fail to catch cross-cloud attack chains. |
| 10 | What is 'log normalization' and why is it tested? | Converting logs from different formats/sources into a common schema so a SIEM can correlate events across heterogeneous cloud services and providers. Exam tip: without normalization, correlation rules can't reliably match fields across sources. |
| 11 | Metrics vs Logs vs Traces — quick match to use case | Metrics → performance dashboards & threshold alerting (e.g., CPU 80%). Logs → forensic detail of a specific event. Traces → end-to-end latency/path across microservices for one request. Exam tip: match the scenario keyword ('request path,' 'threshold,' 'event detail') to the right telemetry type. |
| 12 | Exam trap: 'Enabling control plane logging alone is enough to detect all security incidents' — true or false? | False. Control plane logs miss in-workload/data-level activity (e.g., unauthorized data access, malware execution inside a VM). Data plane logs and network flow logs are also needed for full visibility. Exam tip: a single log source is rarely presented as the correct 'complete' answer. |
