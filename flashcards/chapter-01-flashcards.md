## Chapter 1: Domain 1: Cloud Computing Concepts and Architectures — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | List the 5 NIST (SP 800-145) essential characteristics of cloud computing. | On-demand self-service, Broad network access, Resource pooling, Rapid elasticity, Measured service. Exam tip: the exam may describe a scenario and ask you to name the characteristic it illustrates. |
| 2 | IaaS: who manages the guest OS and above? | The customer manages OS, middleware, runtime, applications, and data. CSP manages virtualization, servers, storage, and networking. Exam tip: responsibility line sits just above the hypervisor. |
| 3 | PaaS: who manages the OS and runtime? | The CSP manages OS, middleware, and runtime. The customer manages only application code and data. Exam tip: PaaS moves the responsibility line up to 'application and data only.' |
| 4 | SaaS: what does the customer still control? | Data classification, user/IAM configuration, and endpoint access. CSP manages the application, runtime, OS, and infrastructure. Exam tip: even in SaaS, the customer is never fully off the hook. |
| 5 | Difference between Private cloud and Community cloud (NIST)? | Private cloud = provisioned for exclusive use by a single organization. Community cloud = provisioned for exclusive use by a group of organizations with shared concerns (e.g., compliance, mission). Exam trap: these two are commonly confused. |
| 6 | What is Multi-cloud vs Hybrid cloud? | Multi-cloud = using multiple public cloud providers side by side (e.g., AWS + Azure). Hybrid cloud = composition of two or more distinct infrastructures (private/community/public) bound together enabling portability (e.g., cloud bursting). Exam trap: these are NOT the same term. |
| 7 | CSA logical model layers, bottom to top. | Facility → Network → Hardware → Resource Abstraction and Control (virtualization/hypervisor) → Applications, with Orchestration as a cross-cutting management layer. Exam tip: customer control increases as you move up; CSP control dominates lower layers. |
| 8 | 'Security OF the cloud' vs 'Security IN the cloud' — who owns which? | CSP owns security OF the cloud (physical facilities, hardware, virtualization infra). Customer owns security IN the cloud (data, identities, access configuration). Exam tip: this split exists in every service model — only the boundary line moves. |
| 9 | NIST: Resource pooling — what does it mean? | CSP's computing resources are pooled to serve multiple tenants using a multi-tenant model, with resources dynamically assigned/reassigned per demand. Customer generally has no control over exact physical location but may specify a higher-level abstraction like region. Exam gotcha: 'no visibility' ≠ 'no location control at all.' |
| 10 | NIST: Measured service — what does it enable? | Cloud systems automatically control and optimize resource use by leveraging a metering capability, providing transparency for both provider and consumer (pay-per-use billing). Exam tip: ties directly to usage-based billing models. |
| 11 | NIST: On-demand self-service — key trait? | A consumer can unilaterally provision computing capabilities (e.g., server time, storage) automatically without requiring human interaction with each service provider. Exam tip: this is what distinguishes cloud from traditional IT provisioning/ticketing processes. |
| 12 | NIST: Hybrid cloud definition. | A composition of two or more distinct cloud infrastructures (private, community, or public) that remain unique entities but are bound by standardized or proprietary technology enabling data and application portability (e.g., cloud bursting for load balancing). Exam trap: Hybrid ≠ Multi-cloud. |
