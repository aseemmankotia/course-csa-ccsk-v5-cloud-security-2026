## Chapter 7: Domain 8: Cloud Workload Security — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | CWPP stands for? | Cloud Workload Protection Platform — protects workloads (VMs, containers, serverless) via vulnerability management, runtime protection, and hardening across the workload lifecycle. Exam tip: CWPP = workload-centric; CSPM = cloud service/account posture-centric. |
| 2 | CWPP vs CSPM — key difference? | CWPP protects the workload itself (runtime of VM/container/function); CSPM assesses cloud account/service misconfigurations. Exam tests whether you can map a scenario to the correct tool category. |
| 3 | Pod Security Standards (PSS) — the three levels? | Privileged (unrestricted) → Baseline (blocks known privilege escalation: no privileged containers, no hostPID/hostNetwork/hostIPC) → Restricted (adds non-root requirement, drops all added capabilities, requires seccomp). Exam tip: know the least-to-most-restrictive order. |
| 4 | Kubernetes namespace — what does it NOT provide by default? | Namespaces alone give no network isolation or resource limits; must pair with NetworkPolicies, RBAC, and ResourceQuotas. Common exam trap: assuming a namespace boundary equals a security boundary. |
| 5 | Kubernetes RBAC: Role vs ClusterRole? | Role = permissions scoped to one namespace. ClusterRole = cluster-wide (or reusable across namespaces via RoleBinding). Exam tip: least privilege favors Role + RoleBinding over ClusterRoleBinding whenever scope can be limited. |
| 6 | Golden image? | A pre-hardened, patched base VM/container image used as the single source for all deployments, replacing the need to patch live instances individually. Exam tip: pairs with immutable infrastructure — rebuild and redeploy instead of patching in place. |
| 7 | Best pipeline stage for container image scanning? | Scan at build time in CI before the image is pushed to the registry, and re-scan images already in the registry as new CVEs are disclosed. Exam tip: this is the 'shift-left' principle — catch vulnerabilities before deployment. |
| 8 | What makes the serverless attack surface unique vs VM/container workloads? | Event-driven triggers (API gateways, queues, object storage events, pub/sub) create many entry points beyond the traditional network layer; each event source needs its own authorization and input validation. Exam tip: 'more entry points, less infrastructure to secure.' |
| 9 | Serverless execution role — best practice? | Scope each function's IAM/execution role to least privilege (specific resources and actions only); never share one broad role across many functions. Exam tip: over-permissioned execution roles are the #1 serverless exam trap. |
| 10 | What does container runtime protection detect? | Anomalous process execution, unexpected network connections, file integrity changes, and privilege escalation attempts inside a running container. Exam tip: it complements (not replaces) pre-deployment image scanning. |
| 11 | Container registry security controls? | Access control on push/pull, image signing/content trust, vulnerability scanning, and image immutability (pin specific tags, avoid 'latest' in production). Exam tip: private registry + signed images = supply chain protection. |
| 12 | Standard reference for workload hardening baselines? | CIS Benchmarks (e.g., CIS Docker Benchmark, CIS Kubernetes Benchmark) provide vendor-neutral hardening baselines for secure default configuration. Exam tip: CCSK guidance references CIS benchmarks as the standard hardening baseline source. |
